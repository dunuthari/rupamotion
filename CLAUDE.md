# Ru Motion — project guide for Claude Code

Ru Motion (Ru · රූ · "form, image" — short for රූප / Rupa; the plugin was called Rupa Motion before) is a dockable **ScriptUI panel for Adobe After Effects**
that builds Google Vids–style SaaS motion: shape morphs, pops, slides, cut transitions, kinetic text,
UI-kit elements, camera parallax and a live, toggleable bounce.

## Commands
- `npm install` — once (installs ESLint for the lint step)
- `npm run build` — concatenates `src/*.jsx` → `dist/RuMotion.jsx` and syntax-checks it
- `npm run lint` — ESLint (ES5 parser, `no-undef`) on the built file
- `npm run test` — mock-ScriptUI smoke test: builds the panel, runs every custom draw routine,
  clicks every tab/chip/button with no comp open, checks nothing throws
- `npm run check` — all three. **Run this after every change.**

`dist/RuMotion.jsx` is the only file the user installs. Never hand-edit it; edit `src/` and rebuild.

The group icons are a vertical rail on the left (`nav` in `buildContent`); chips and the feature card sit to its right.
Tabs in the panel (rail order = `GROUP_ORDER`): Layers & Timing · Animate · Text · Transitions · Build · Camera · Flow · Style (rail label for Layers & Timing is "Layers").
Animate = Quick (In / Out / Move / Tools sections) + Shape morph, Pop, Move in/out, UI list stagger, Hold push-in. Text = **Effects** (Reveal: typewriters, Letter Blur, SaaS Text Preset 1, Two-Line Stack · Style: Word Highlight, Hero Zoom/Blur, Blur Out, Delete Out · Presets: the .ffx files) + Text + Icon (+ Star Swipe). Build = Smart shape, UI Kit elements, Stock grid wall. Feature chips are drawn as one segmented control in the browser preview and the CEP panel (`.chips` track, raised `.chip[aria-selected]`, child row `.chips-sub`; chosen from five mock-ups). Chips inside a tab are ordered by `CHIP_ORDER` (stable; unlisted features go last). `build.js` `LABELS` gives the .ffx buttons readable names (sorted by label); the test reads them through `labelOf`.
Add a feature with `feature("Group", "Name", function (p) { ... })` in `07_ui.jsx`; wrap its action in `run("Label", fn)`.

## ExtendScript rules (After Effects runs ES3!)
- No `let/const`, arrow functions, template strings, `Array.prototype.indexOf/map/forEach/filter`, `String.trim`, `JSON`.
  Use the helpers `trim`, `num`, `splitList`. ESLint runs with `ecmaVersion: 5` to catch most of this.
- **Expressions** written into AE must work in both the Legacy and JavaScript engines: use `add/sub/mul`
  for vector math, never `+`/`*` on arrays.
- After `addProperty()` on a property group, earlier references into that group can become invalid —
  re-fetch (see `addVec`). Add effects **before** grabbing other property references.
- Effect *point* parameters on **shape and text layers** live in comp space (see locked gradients below); footage/solids use plain layer pixels.
- Locked gradients (`addLockedGradient`) feed Ramp points through `thisLayer.toComp()` on shape/text layers, so
  they move, scale and rotate with the element. Don't use a fixed half-comp offset there: it is only right while the
  layer sits at the comp center.
- Flow easing: untie keys (`setTemporalContinuousAtKey`/`AutoBezier` false) before `setTemporalEaseAtKey`, or later curves are
  rejected; read the ease back and retry. Linear is a bezier with handles on the straight line, not the Linear interpolation type.
- `layer.parent = x` keeps the layer from jumping (AE shifts the child's own position to cancel the parent's offset). So link first,
  while the parent is at rest, and only then set offsets on the parent (see `doSwipeCut`). Tests' fake layers must do the same.
- Track mattes: use `setMatte()` (new `setTrackMatte` API on AE 2023+, falls back to `trackMatteType`).
- Drop Shadow opacity is stored 0–255 (38 ≈ 15%).

## ScriptUI rendering rules (learned the hard way)
- **Never put `onDraw` on a container that holds controls.** AE then stops drawing the children
  (only native edittexts survive). Custom drawing is allowed only on leaf elements: buttons, empty groups.
- AE paints every group with a solid background, so a "card" is a group with `graphics.backgroundColor`
  plus a bold `statictext` title (`card()` in `07_ui.jsx`). Large cards can't have rounded corners;
  buttons, chips, toggles, tab tiles and the logo are custom-drawn and rounded (`rrPath`).
- Native edittext/dropdown always render dark, which is why the panel ships a single **dark** theme.
- Redraw a custom control with `redraw(ctrl)` (`notify("onDraw")`) or `repaint(ctrl)` (hide/show). Buttons made by
  `styleButton` show a pressed state on mouse down; `btn()` keeps it through the action so quick clicks are visible. Toggles expose `.value` and `.onToggle`.

## Performance notes
- Feature cards are built lazily (`ensureBuilt` in `buildContent`) the first time their chip/tab is shown; tests set `$.global.RuMotionEager = true` to build all of them.
- Preferences are written only when the saved tab/feature actually changes; tab and chip repaints use `redraw` (no hide/show, which re-lays-out the panel).

- The panel always opens on the first tab (no saved tab, so no preference writes while browsing). The content area is a fixed-height viewport (`setViewH`, min = max) with a scrollbar; ScriptUI never delivers the mouse wheel to panels (`onWheel` is a harmless best-effort), so scrolling is also by dragging any empty area of a card (`hookDrag`) and Up/Down/PageUp/PageDown (`keyScroll`); both unverified in AE. Docked panels re-fit the height with a dead band (`fitScroll`); floating windows keep it fixed. Buttons redraw only from mouse events (`btn` adds none).

## CEP panel (`cep/`)
`npm run cep` builds `cep/RuMotion/` (manifest, `index.html`, `jsx/RuMotion.jsx`) and `cep/RuMotion-CEP.zip` (with `install.bat` / `install.command`). The HTML panel (`cep/app.js`, CSS and markup taken from `preview/index.html`) draws no logic of its own: `RuMotion.jsx` is loaded with `$.global.RuMotionBridge = true`, builds the ScriptUI panel on a window that is never shown, and `$.global.RuBridge` (`exposeBridge` in `07_ui.jsx`: `meta`, `feature(i)`, `set`, `click`, `cut`) describes each card as JSON (`brCard`) and drives the real controls. So every effect is the same code in both panels and new features appear automatically. Custom-drawn stages (Text + Icon / Star Swipe preview, Flow graph) are not controls: the CEP side redraws the Flow graph and presets itself and skips the stages. Mouse wheel works in CEP. Unverified in AE: evalFile path handling, the debug-mode install, `__adobe_cep__.getSystemPath`. The ScriptUI `dist/RuMotion.jsx` stays the single-file install.

**Live preview stages (CEP only, `cep/app.js`)**: Text > Effects gets `buildFxPreview` (a stage that plays the chosen effect on a sample line, a "Preview text" field saved in localStorage) and Text + Icon gets `buildTiPreview` (words slide apart, icon slot opens; it reads the Sentence field and Icon position dropdown through `ctlMap`). In the Effects card a click on an effect button **only previews** (`ctx.fx`, class `pv-on`); the added *Apply <name>* button sends the real `click(id)`. This is CEP behaviour only: in the ScriptUI panel the buttons still apply at once. `PV_FX` maps button labels to preview animations: built-in effects use their real timings, the `.ffx` presets are **guesses from their names** (`guess: 1`, shown as "approximate"), Motion Type and SaaS Style 3/4/5 are rebuilt from the settings read out of their `.ffx` files (which animator properties, Based On words / letters / lines, offsets; the keyframe timing was not read), also marked approximate; a label without an entry shows "no preview yet". The stages (`.pv-stage`, `.cs-stage`) are `position: sticky; top: 0` so they stay in view while the card scrolls (no `position: relative` on them, it would cancel the pinning). New effect buttons need a `PV_FX` entry to get a preview. **Animate stages** (`buildAnimPreview`, `AN_FX` keyed by card title, CSS `.an-*`): every Animate card gets the same kind of stage with a lime sample layer that loops the effect (2.4 s) and follows the card's own controls, found by label (`c.num/bool/sel`). Quick, Pop and Move in / out: a click on an effect button only previews it (`wants(item)` limits this to the effect buttons, so Quick's Tools buttons still apply at once) and the added *Apply <name>* button sends the real click; Shape morph, UI list stagger and Hold push-in have one action button, so their stage just shows the current settings. Distances are scaled to the stage (400 px = the stage width); the previews are illustrations, not the real curves.

**Captions (English Transcript)**: Text > Captions, **CEP panel only** (the card is registered only when `$.global.RuMotionBridge === true`). Select an audio/video layer, click *English Transcript*: `cep/app.js` `runAction` asks the bridge for the layer (`captionSource`: file path, start/in/out/stretch), runs `cep/transcribe.js` in the panel (Node is enabled in the manifest with `--enable-nodejs --mixed-context`), then sends the lines back (`captionBuild` -> `buildCaptions` in `src/06_captions.jsx`): one `Ru Caption N` text layer per line, bottom-centred, Style bold font, optional soft shadow; source times map to comp time with `startTime + t * |stretch|/100` and are clipped to the layer's in/out. `transcribe.js` is offline whisper.cpp: engine = `whisper-cli` found on PATH / `%APPDATA%\RuMotion\whisper\engine` (Windows: downloaded from the latest `ggml-org/whisper.cpp` release asset `whisper-bin-x64.zip` and unpacked with `tar`/PowerShell; Mac: `brew install whisper-cpp`), model = `ggml-{tiny,base,small}.en.bin` from Hugging Face into `...\whisper\models`, audio = ffmpeg if installed else Web Audio decode + `encodeWav` (16 kHz mono), args `-l en -oj -ml 42 -sow -pp`, output parsed from `<prefix>.json` (`offsets` in ms) and cleaned (`cleanSegments`: sound tags dropped, overlaps trimmed, 0.4 s minimum). The button doubles as Cancel. `tests/transcribe.test.js` runs the pipeline with a fake engine/ffmpeg and a local web server (part of `npm run check`). **Unverified in real AE/Windows**: Node inside the CEP panel, the GitHub asset name/zip layout, the whisper.cpp flags and JSON shape on the real binary, the downloads, Mac via Homebrew. **Caption animation** (same card, `src/06_captions.jsx`): there is deliberately **no Font section** (removed on request). New captions get a fixed look (`captionSettings` defaults: white, Style bold font, 64 px, centred, 10% above the bottom, soft shadow, wrapped at 88% width; the old font/outline/box/case code still exists behind those defaults because `CAP.family`, `CAP.size`... are simply absent). The card has *Transcribe* and *Animation* (In: none/fade/pop/slide up/blur in/typewriter/word by word; Out: none/fade/slide down/blur out/pop out; lengths in frames capped at 45% of the caption each; curve expo/smooth/linear; slide distance) and the buttons *Apply to all captions*, *Apply to selected*, *Select all captions* (there is no Reset animation button, removed on request). `applyCaptionStyle(comp, layers, full)`: a new transcript passes `full` (text styled too); the buttons only rebuild the animation (`capGeoOf` reads the resting position at the middle of the caption), so font, size, colour and position changed by hand in AE are never touched. If the Font controls ever come back (`cs.fontControls` = `CAP.size` exists) Apply restyles the text again. Animation is plain keyframes on opacity/position/scale, a `Ru Caption Blur` effect, or a `Ru Caption In` text animator (Range Selector Start 0 -> 100, Based On Characters/Words) for typewriter/word by word. Not built: highlighting the spoken word (needs word timing), a bounce curve, editing the transcript lines. **Unverified in AE**: the text animator/selector matchNames (`ADBE Text Opacity`, `ADBE Text Percent Start`, `ADBE Text Range Type2`), `ADBE Gaussian Blur 2`, `layer.comment`.
**Transcript editor** (Text > Captions > Transcript, CEP only): after transcribing, the card lists one row per `Ru Caption` layer (start time | editable words | small "+"). Rows are plain, no colour change for edited/split rows. Enter inside a row splits it in two (time split proportionally by letters, each part >= 0.8 s), Backspace at the start joins with the previous row, focusing a row moves the playhead to it (`captionGoto`). "+" adds an empty caption: fills the gap after the row if >= 0.4 s (max 3 s), after the last row adds 2 s, else halves the row if it is >= 0.8 s, else a toast. Nothing changes in AE until *Apply changes* (one undo group "Edit captions"); *Reload from timeline* re-reads. Bridge: `captionList()`, `captionApply(json)` -> `captionApplyData` in `src/06_captions.jsx`, `captionGoto(name)`. Rows are `{name, from, start, end, text}`; a row without a known `name` is a new layer duplicated from `from` (error if none). Algorithm: normalise touched layers (`capRestState`, strips animation), retext keeping the bottom edge (`capRetext`), set times, remove layers no row refers to (joins), renumber `Ru Caption 1..n` via temp names, rebuild animation on touched layers only. Tests: `transcript editor` block in `tests/ui.test.js`. **Unverified in AE**: `layer.duplicate()` on text layers, `sourceRectAtTime` of empty text layers.
**Caption word highlight** (Text > Captions > Style, `capWordStyle` in `src/06_captions.jsx`; CEP card `buildCapStyle` in `cep/app.js` with live preview): looks Plain / Word box / Word colour / Word pop / Underline / Karaoke fill (`CAP_LOOKS`), text colour, box colour, roundness, other-words brightness, Dimmed/Full (`CAP.hl*`; default Plain, so nothing changes until the user picks a look and presses Apply). Word times: `transcribe.js` now runs `-ojf`, `wordsFromTokens` turns tokens into `{s,e,w}`, `cleanSegments` keeps them only when they match the cleaned text; `buildCaptions` stores them in the layer comment as `ru:<text>\nrw:s,e;s,e` (fractions 0..1 of the caption; `capPutComment`, `capWordTimes`, `capOrig` reads only the first line); no word times (old captions, edited text) = even spread by letters. Built with Index-unit text animators on Words (`Ru Word Dim` before the spoken word, `Ru Word Dim 2` after, `Ru Word Active`, or `Ru Word Fill` on Characters for Karaoke) whose Start/End expressions read the caption's own `time - thisLayer.startTime` against a baked word-start list (marker `// Ru Word Style`), plus for Word box / Underline a shape layer `Ru Caption Word N` (rect size and position expressions, parented to the caption so it follows its slide/scale, fades with it; moved below it). `capResetFx(L, comp)` removes the animators and that layer; `captionApplyData` renames the highlight layers when captions are renumbered. Word box is centred on the text through the vertical middle of the caption's own text rectangle (where its anchor sits) plus one line step per line, box height 1.1 em. After every apply `capCollapse` selects the touched captions and their highlight layers and runs menu command 2771 ("Reveal All Modified Properties") once, because After Effects opens the property tree of layers a script adds animators to and has no API to close it (community-reported toggle, **unverified**; it then restores the selection). `capResetFx` also removes any `Ru Caption Word` layer parented to the caption, so a new look replaces the old one. **Unverified in AE**: parent-space position of the box (child position relative to the parent's anchor), `ADBE Text Scale 3D` / `ADBE Text More Options` > `ADBE Text Anchor Point Option` for Word pop, whisper.cpp `-ojf` token timestamps on the real binary (tests use a fake JSON), the Index End expression for karaoke.
Sinhala captions were tried (Whisper models, then a Google key, then an offline converted model) and **removed on request**; nothing Sinhala remains in the Captions tab. English only.

**Windows installer** (`installer/`, `npm run installer`): `RuSetup.cs` (C# WinForms, owner-drawn dark/lime window, no console) + `LogoData.cs` (logo polygons generated from `LOGO_SHAPES`) + `ru.ico`; `build.sh` zips `cep/RuMotion` into the exe as resource `RuMotion.zip`, compiles with Mono `mcs` (`apt install mono-mcs mono-devel`) to `cep/RuMotion-Setup.exe` and adds it to `RuMotion-CEP.zip`. Website box: set `SITE` in `RuSetup.cs` (empty = hidden). Rebuild after every `npm run cep`. Unsigned (Windows shows Unknown publisher; needs a code-signing certificate). ## Text group
**Text + Icon**: the user types 2–6 words, picks the icon slot (before / between / after words) and optionally browses for an icon file
(else a built-in sparkle). Words slide apart and grow (`TI.pos*`/`TI.scl*` curves fitted to the reference), a lavender->magenta highlight sweeps
word to word, and the icon is deliberately NOT animated (the user does that). All words share one baseline (anchor at `top/2` of the ascender box, so descenders like the g in "beauty" don't shift a word). "Icon gap (px)" adds to the final slot (undo and rebuild to change it). Text and icon default to the Style gray (`textGray`); the highlight sweep is OFF by default. The Move null is moved to the top of the layer stack, sits at the comp centre with its anchor at its own centre (50,50), so scaling/rotating it pivots on the middle of the frame; children are stored relative to it (`local = comp position - (null position - null anchor)`). Keep the `TI` numbers unless asked. Tests use a fake AE with text
layers, shape layers and text animators; if you change the layout maths, update the independent arithmetic in `tests/ui.test.js`.
**Star Swipe** (`doStarSwipe`): two sentences share one baseline at the comp centre; one `Ru Star Swipe · Move` null (anchor at its own centre, on top of the stack) carries the star, a soft-edged half-plane matte on each side and an optional glow trail (16 thin slices whose fill opacity rises 0% at the tail to 100% at the star, melted by a blur), all parented to it. Sentence 2 is alpha-matted by the matte to the left of the star, sentence 1 by the one to its right, so the star wipes one into the other. The star starts and stops just outside the wider of the two sentences (gap = max(0.7 x star size, 1.5 x softness)) and stays in the frame. Only the Move null (and the star's optional half-turn) is keyed, with the `SS.curve` ease. Wait/sweep times, curve, trail length and softness are *estimates* read off a clip, not frame-measured, so they are fields/one constant: tune on request. Text and star default to gray, the trail to magenta `#C158BE`.
Star Swipe is registered as a child of Text + Icon: `feature(group, name, build, parentName)` puts a feature under another chip as a second-level chip row (top row: Motion | Text + Icon; second row under Text + Icon: Text + Icon | Star Swipe). Use the 4th argument for any future sibling effect.
**Typewriter** (`doTypewriter`): a plain button at the Reveal section of Text > Effects, no settings and no chip of its own. It types out the selected text layer(s) at the playhead (single line, explicit line breaks, or wrapped paragraph text): the whole effect runs on **two keyframes**: a Slider Control effect named `Typed` on the helper (caret) layer goes linearly from 0 to the number of letters (first letter after `TW.hold`, then `1/TW.cps`), and everything else is an expression reading it (`Math.floor(slider)`): a text animator with Opacity 0 and a Range Selector in *Index* units hides everything from `Start` on (Start's expression points at the helper layer by name, e.g. `Ru Typewriter · Caret 4-12345`; names carry a unique tag so presses never clash), the caret's position and blink expressions, and the centring shift. Retime the effect by moving the two slider keys. A second press removes the old animators, the old helper layer and the centring expression. All expressions use only `Math.*`, `time`, `value`, `key(2).time` so they run in both engines; each starts with the marker `// Ru Typewriter`. Letter and word positions come from `layoutText`: every prefix of every line is measured on a scratch point-text layer that copies the layer's own character style (`prefix + "|"` minus the bar width so trailing spaces count); lines come from explicit breaks (\r, \n, \u0003 — each break is one letter, the caret hops to the next line) and, for paragraph (box) text, from a greedy word wrap against `boxTextSize[0]`; line spacing is `leading`, else 1.2 x font size. Paragraph (box) text is NOT drawn from the layer origin: lines start at `boxTextPos[0]` (plus the justification offset inside `boxTextSize[0]`), and the first baseline is the top of the layer's `sourceRectAtTime` minus the top of the same first line on the point-text scratch layer (`layoutText().baseY`, 0 for point text). That is why both effects must start at the text, not at the layer position/anchor. Only a SINGLE line of POINT text (no position keys, no parent) is kept centred while it grows (position steps by half a letter width per letter); multi-line text and box text stay where they are and type from the left. Centre/right justification is handled for point text (around the origin) and for box text (inside the box). The caret is a separate thin shape layer in the text's fill colour (the helper layer); it is on from the start, follows the slider through a lookup-table expression, blinks `TW.blinks` times after the last letter (computed from `key(2).time`), then goes away. Pace (14 letters/s), first-letter hold, caret size and blink timing are read off a clip, not frame-measured: they live in `TW`. The clip's blue last word and camera zoom were deliberately left out ("no other effects").
**SaaS Text Preset 1** (`doSaasRoll`, built-in button, replaces the removed .ffx of the same name): select TWO text layers (the LOWER one in the stack is the sentence that is visible first and leaves, the UPPER one is the sentence that arrives; selection order does not matter, and they should sit in the same spot), or ONE text layer holding the two sentences on two lines (explicit break or wrapped paragraph). `rollOne(comp, L, t0, mode)` with mode `out` (moves up, amount = u), `in` (starts one line lower, amount = 1 - u) or `both` (one layer); each layer gets its own window, slider and animator. A mask `Ru Roll Window` one line tall (from `SR.top` em above to `SR.bottom` em below the first baseline, very wide) clips the layer; an animator `Ru SaaS Roll` moves every word up by one line height (`lineStep`), so line 1 leaves through the top and line 2 rises into its place. Two keyframes: a `Roll` slider effect on the text layer, 0 -> T seconds; an *Expression Selector* (`ADBE Text Expressible Selector`, Amount expression, ease-out cubic) turns it into each word's own amount with its line's own stagger (`SR.stagger` 0.08 s per word, `SR.dur` 0.2 s). The expression works whether the selector is Based On Words or Characters (lookup tables for both). If the Expression Selector cannot be created the whole block rolls with two keys on the animator's Position instead. Timings read off a clip; the emoji and background colours of the clip were left out. The matchNames of the Expression Selector (`ADBE Text Expressible Selector`, `ADBE Text Expressible Amount`) and of its Based On property are from memory and unverified in AE.
**Typewriter Block** (`doTypewriterBlock`, second button in the same row): word by word (`TB.wps` = 6 words/s, first word after `TB.hold`), also on **two keyframes** (the `Typed` slider on the block layer, 0 -> number of words). Two text animators on Index units / Based On *Words*: `Ru Typewriter <tag>` (Opacity 0, `Start` = floored slider) and `Ru Typewriter Wave <tag>` (Fill Color blue, Range Shape *Ramp Up*, Start = typed - `TB.wave`, End = typed, so the last words are blue, strongest on the newest, fading back to the layer's own colour). The block layer (10 colour slices, gradient cyan-blue to periwinkle, 100 px wide) has position / scale / opacity expressions (lookup tables from `layoutText`) so it sits on the next word at that word's width and disappears when the last word lands. Word positions and line wrapping come from the same `layoutText` as Typewriter, so it follows explicit breaks and wrapped paragraphs (the block drops one line per wrap). Box geometry as for Typewriter (`boxTextPos`, `baseY`); unverified on real paragraph text in AE beyond the screenshots that led to it. Camera zoom and the clip's later scenes were left out.
**Text + Icon panel preview**: the AE panel itself shows a picture of the finished line (`drawTiStage`, on an empty leaf group; words, icon slot and sparkle laid out with `tiLayout`/`TI`, scaled to fit, redrawn when the sentence, icon position, size, gap or colours change). Star Swipe has the same kind of stage (`drawSsStage`): the sweep frozen at 50%, with sentence 2 drawn letter by letter behind the star, sentence 1 ahead of it, the glow slices and the star (no clipping in ScriptUI, so letters are drawn individually from `approxWidth`). Both stages are static; the animated replay exists only in the browser `preview/`. `colorChooser` returns `{get, onChange}` so a card can redraw when a colour changes.
The Text group has a sub-group chip row (`SUBGROUP_CHIPS`); the `.ffx` presets live in the **Motion** sub-group. More sub-groups can be added as extra `feature("Text", ...)`.

`npm run build`; each becomes a button (file name = label). They are embedded in `dist/RuMotion.jsx`, which stays the only file to install.

**Showreel styles** (`src/06_text_styles.jsx`, seven buttons after SaaS Text Preset 1 in Text > Effects (Reveal/Style sections), no settings, select the layer and click): read from a 30 s SaaS text showreel. Hero Zoom (scale 320% -> 100% over 1.0 s, blur 80 -> 0, fade 0.35 s; any layer) · Hero Blur (94% -> 100%, blur 36 -> 0, 0.9 s; any layer) · Blur Out (100% -> 92%, blur 0 -> 30, opacity out over 0.55 s; any layer) use plain keys with cubic-bezier eases. **Shape morph** (`src/03_animation.jsx`, Animate > Shape morph; `doMorph`, `morphLayerKeys`, constants in `MORPH`): works on any two layers (`isMorphLayer`: shape, text or AV layer; **shape and text layers are not `instanceof AVLayer` in After Effects**). It is a bounds morph, the same for every layer type (the old point morph, mask morph, fit / cross-fade / colour / hide options were removed on request): every number was measured from the user's frame-by-frame screenshots of a reference morph at 25 fps (S = playhead). First layer: **Position** 4 keys at S, S+0.16 (pull-back = 5% of the distance backwards + 9.1% sideways, `nx = uy, ny = -ux`), a roving key (`setRovingAtKey`, placed at S+0.38) 20% of the pull-back past the start on the other side, S+0.64 arrival (linear) on the second layer's centre; eases out 5% / in 90% / out 90% so the wind-up is quick and the launch accelerates; spatial tangents make the path swoop under the straight line and arrive from the side (directions estimated from three measured positions, lengths D/3: **an approximation of the reference path**). **Scale** 100 -> 80% -> 100 at S+0.08 / 0.40 / 0.72. **Rotation** to the second layer's rotation S -> S+0.64 (no bounce). Effect `Ru Morph Transform` (built-in Transform, `ADBE Geometry2`, properties addressed by index: 1 anchor, 2 position, 3 uniform scale, 4 scale height, 5 scale width, 8 rotation; anchor and position expressions follow the layer anchor, `thisLayer.toComp(...)` on shape/text layers): Scale Width/Height 100 -> second layer's size / first layer's size (`shapeCompBox`) from S to S+0.64 with a 95% slow start and no bounce, Rotation 0 -> 18 degrees (sign follows the x direction; the 18 is derived from one measured post-arrival value, the reference key value was not visible) -> 0 at S+0.16 / 0.48 / 0.80. **Bounce** (`morphBounceExpr(div)`, marker `// Ru Morph Bounce`): `value + v * amp * sin(freq*t*2pi) / exp(decay*t)` after the nearest previous key, v = speed one tenth of a frame before it, amp = Amplitude slider / 2000 (position), / 200 (scale), / 300 (effect rotation), decay = 5 / Decay slider; sliders `Ru Morph Amplitude` (100), `Ru Morph Frequency` (1.5), `Ru Morph Decay` (1.0) as Slider Control effects on both layers, set from draggable sliders in the card (`sliderRow`; bridge kind `s`, `input[type=range]` in `cep/app.js`). **Swap**: Opacity expressions show the first layer until its 4th position key and the second layer from its own 4th position key on; the second layer gets the same path (shifted onto its own position), the same scale dip and lean, no stretch. The Transform effect can clip content that is stretched beyond the layer's own bounds. The reference tool's protected `.jsxbin` was never opened; the user supplied screenshots of its keyframes and of the expressions it leaves on the layer, and the code here is written for this project. Not built: many-to-one, pairs, no-pull-back modifier. Tests: `shape morph` in `tests/ui.test.js`; **unverified in AE**: the Transform effect's property indices, roving + spatial tangents from script, parented or 3D layers.

**Stagger order** (`SEL_ORDER`, `withOrder`, `orderLayers`, `ORDER_LABELS` in `01_core.jsx`): `selLayers` returns the selection in the chosen order (Top to bottom by layer index = default, Bottom to top, Selection order, Left to right by `compBounds`). Quick ("Several layers" section: Stagger (frames) + Order, used by every In / Out / Move button) and Pop (Stagger + Order rows) wrap their action in `withOrder(...)` and pass the stagger to `doFade` / `doBlurFade` / `doPop` / `doMove`, which already spaced layer i by `i * stagger` frames. Other tools see the default order.

**Number counter** (`src/06_text_counter.jsx`, Text > Effects > Number counter section): From, To, Decimals, Prefix, Suffix, Thousands separator, Short form (k / M), Curve (Ease out / Linear / Ease in-out). The selected text layer gets a Slider Control `Ru Counter` with two keys at the playhead, From -> To over `NC.dur` = 1 s (the user retimes by dragging the second key; there is deliberately no Duration field), eased with `easeBetweenKeys`, and a Source Text expression (`counterExpr`, marker `// Ru Counter`, ASCII only, both engines: manual thousands grouping, no `toLocaleString`). **Anchor point** (`doAnchor(ix, iy, kfMode)` in `06_tools.jsx`, Layers > Layer operations > Anchor point): nine arrow buttons (3 rows, ix / iy in 0 / 0.5 / 1 of `sourceRectAtTime`, falling back to the layer width / height) move the anchor and shift the position by the same offset through the layer's scale and rotation (`anchorShift`, z rotation on 3D layers), so nothing moves on screen; separated X / Y positions handled. Keyframed properties have every existing key shifted (position keys by the shift at their own time), so the animation does not change; `kfMode` 0 (a new key at the playhead) still exists in `doAnchor` but the "If keyframed" dropdown was removed on request, the card always passes 1. There is deliberately no preview stage. Tests: `anchor / counter / order` in `tests/ui.test.js`. **Unverified in AE**: spatial tangents after `setValueAtTime` on existing position keys, parented layers whose parent is rotated.

**Follow Path** (`doFollowPath` in `06_tools.jsx`): "Front faces" (Right / Up / Left / Down, `FRONT_OFFSET` 0 / 90 / 180 / -90 degrees) is added to the Orient along path rotation expression, because the tangent angle alone assumes artwork that points right (a car drawn nose-up needs Up). Orient off removes a rotation expression the tool wrote earlier.

**Fixed cut bar** (`src/06_layer_cut.jsx`, built at the bottom of `buildContent`, visible in every group): three secondary buttons in a row directly in the window, below a `fill` spacer so it stays at the bottom. They act on the selected layers at the playhead, only on layers the playhead is strictly inside (locked layers and layers the playhead is outside of are left alone; if none qualify an alert explains why). Cut Before: `inPoint = playhead`. Cut After: `outPoint = playhead`. Split: `duplicate()` the layer, copy `inPoint = playhead` and `outPoint = the original out`, original `outPoint = playhead`. The end that must not change is written back and read back (`pin`), because the user reported the right-hand piece of a Split coming out longer than the original (cause not reproduced; it is guarded against rather than understood). Nothing is ever deleted. Whether the spacer really pins the bar to the bottom when the panel is taller than its content is ScriptUI layout behaviour, unverified in AE.

**Logo** (`logo()` in `07_ui.jsx`, `LOGO_SHAPES`): the header logo is the user's artwork, traced into two white polygons (the swoosh, 82 points, and the inner drop, 48 points; flat x,y lists in 0..1 of the square icon, simplified with a 0.9 px tolerance on the 500 px original) drawn in the near-black `onPrimary` over the lime primary rounded square (traced from the lime/black R artwork, scaled 1.12 about the centre). ScriptUI paths have no curves, so it is a polygon outline (smooth at 26 px). To change the logo, re-trace the PNG (skimage `find_contours` + `approximate_polygon`) and replace the arrays; the browser preview uses the same outline as an inline SVG in `.logo`.

**About window** (`showAbout()`, `ABOUT` in `07_ui.jsx`): a modal dialog (logo at 64 px, name, version, a How it works card, What's inside / Good to know cards, `Made by Tharindu Lakshan · tlakshan10106@gmail.com`, a Get started button). ## Naming / compatibility
- Created layers/effects/animators use the `Ru ` prefix (renamed from `MK ` on request, together with the plugin name), and
  expression comments keep the `"Motion Kit"` marker on purpose: `Bounce Physics`' "own expression" check and the live-bounce
  expressions depend on it. Projects made before the rename carry `MK Bounce` / `MK Bounce Strength`: `bounceNames()` still
  recognises both pairs and the bounce expression falls back to the old names, so old layers keep working. Layers named `MK ...`
  are still skipped by Swipe cut as tool layers (`^(Ru|MK) `). Everything else the tool made before the rename is just a normal layer.
- Swipe cut builds three linked `Ru Swipe · Move / Out / In` nulls (anchor and position 0,0 so links don't move clips); only the
  Move null is animated. Don't turn it back into an effect on an adjustment layer. The move is short (27% of the frame, 15
  frames each side, keys at cut-16 and cut+15, ease 0.9/0/0.1/1) and the clips are trimmed to a hard cut: both numbers come from
  measuring a hand-made version, so keep them unless asked.
- Settings key is `MotionKit_v1` so saved presets carry over. Don't rename without a migration.
